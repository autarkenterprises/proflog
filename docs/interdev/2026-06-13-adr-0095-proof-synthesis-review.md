## Findings

1. The core synthesis idea is viable.

   Directly invoking the private `sjas-tableau-proof-closeo` relation on the
   beta case produces a raw sigma binding for the fresh proof variable and
   wraps it in the expected `sjas-synthesized-citation` evidence. The failure is
   not that the profile close hook cannot synthesize.

2. The raw answer state is produced before export.

   Calling `program-raw-answer-states` with the ADR-0095 bindings
   (`willard-sjas-answer-theory-closeo`, `*defer-residual-calls* false`) yields
   a raw state whose sigma binds the proof variable to a compact proof-code
   term. The public result disappears after that point.

3. `export-program-answer-record` drops the raw state.

   Exporting the raw state returns `nil`, even with residual completion disabled
   via `{:complete-residuals? false}`. This localizes the immediate public
   failure to answer export/admissibility, not tableau closure.

4. The synthesized proof-code term is non-admissible.

   Reverse use of `sjas-public-code-byteso` for the fixed
   `sjas-axiom-proof-bytes` currently generated:

   ```clojure
   (app code-1590 ...three args...)
   ```

   The expected public compact certificate is:

   ```clojure
   (app code-3 ...three args...)
   ```

   The generated `code-1590` term is not admissible in the system language, so
   `export-answer-record` rejects it. A direct check showed:

   ```text
   :generated-head code-1590
   :declared-arity 1590
   :admissible false
   :expected (app code-3 ...)
   :same false
   ```

5. Root cause: the compact-code reader is not mode-complete for generation.

   In `sjas-code-byteso`, the relation obtains `byte-count` from
   `code-constructoro`, but does not relate `byte-count` to the actual length
   of `args`. The proof-free `sjas-code-bytes-coreo` has the same shape.

   That is acceptable for ground presented-code reading because malformed
   terms such as `(code-1590 ...three args...)` are not normally supplied by
   the builder. But ADR-0095 exposes the reverse mode, and the relation can
   generate a constructor whose arity does not match the generated byte list.

6. The synthesis branch duplicates part of the `tableau-proof/3` preamble.

   The branch manually reconstructs the negated `tableau-proof` literal instead
   of reusing `sjas-tableau-proof-callo`. This is understandable because a fresh
   object proof variable needs to be bound through `equality/unify-termo`, but
   it risks drifting from the existing single-read proof-code discipline guarded
   by the source-audit tests. Prefer extracting a shared “destructure
   tableau-proof args” helper over long-term hand duplication.

## Recommended Next Steps

1. Keep the two ADR-0095 citation-synthesis tests red.

   They are good end-to-end tests for the public behavior required by the ADR.

2. Add smaller red tests before fixing the implementation:

   - compact-code reading rejects malformed arity terms such as
     `(code-1590 ...three args...)`;
   - reverse construction from `sjas-axiom-proof-bytes` yields an admissible
     canonical compact proof certificate;
   - the raw synthesized sigma state exports to a public answer record.

3. Repair the compact-code relation at the source of the mode gap.

   Add or reuse a counted compact-argument relation so `code-N` and the number
   of byte arguments are related in both directions. The existing
   `code-args-build-counto` / `sjas-internal-code-termo` path is the closest
   local pattern because it reconstructs a canonical compact code term from
   bytes and a counted arity.

4. Do not use generic `sjas-public-code-byteso` backward for citation
   construction until the arity issue is fixed.

   The synthesis branch should bind `proof-code` to a canonical public code
   term for `sjas-axiom-proof-bytes`, then validate axiom membership as it
   already does. This preserves the relation's purity while avoiding
   non-canonical, non-admissible compact terms.

5. Refactor the tableau-proof literal preamble after the red tests localize the
   fix.

   A reasonable split is:

   - a shared helper that walks/destructures the negated `tableau-proof/3` atom
     into `system-code`, `theorem-code`, and `proof-code`;
   - the existing checking helper that reads proof-code bytes from a supplied
     public proof term;
   - the new synthesis helper that constructs and binds the public proof term
     from known bytes.

6. Rebase or merge ADR-0095 onto current `main` after the focused tests are
   green.

   `main` now includes ADR-0093's canonical core.logic regression suite and
   ADR-0094's LVar equality fast path. Once ADR-0095 is green locally, rerun:

   ```text

   lein test :only proflog.willard-sjas-test/sjas-tableau-proof-synthesizes-selfcons-citation
   lein test-proflog-fast
   lein test-proflog-extended
   ```

   Then run any focused SJAS selectors touched by compact code reading before
   committing ADR-0095.
