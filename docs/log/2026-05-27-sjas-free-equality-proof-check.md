# SJAS Free Equality Proof-Check Closure

Date: 2026-05-27

## Context

ADR-0073 Track 1 replaces proof-predicate shortcuts with explicit
object-language proof checking. Earlier work made `free-close` encodable in the
SJAS proof-code grammar, but the local SJAS checker still did not consume a
decoded free-constructor equality closure. A proof of `neq(0,1)` therefore
could be generated by ordinary Proflog as `(conj (free-close))`, encoded as an
SJAS proof certificate, and decoded by `tableau-proof/3`, while the final
certificate validation had no corresponding SJAS-side rule.

## Change

`sjas-proof-check-close-agendao` now has a direct positive-equality closure
clause. It selects an agenda formula, substitutes the current branch
environment, recognizes an equality literal, and calls
`equality/eq-contradictiono` relation-style over the current equality
substitution. The branch preserves `sigma` and the saved disequality list
because immediate free-constructor contradiction closes the branch rather than
adding a new binding.

The focused red test first showed that a decoded target
`true and eq(0,1)` with proof `(conj (free-close))` was rejected. After the
change, the decoded checker accepts that proof without invoking
`kernel/prove-programo`. A public `tableau-proof/3` regression also validates
an encoded certificate for the SJAS theorem `neq(0,1)`.

The executable correspondence audit now classifies `free-close` as relevant
closure evidence rather than unresolved equality machinery. Richer equality
constructors such as `eq-step`, triggered calls, disequality closure, and
reflexive closure remain unresolved Track 1/Track 2 obligations.
